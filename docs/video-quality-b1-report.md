## Эксперименты (этап A: montage.quality_audit)

Эксперименты в `/tmp` (не входят в репозиторий). Источник: `montage_work/9a7cf622/project_video.MOV`
(iPhone HEVC 1280x720, 30 fps, bt709, SDR).

### 1. Пригодность OpenCV

`cv2.VideoCapture` корректно декодирует `yuv444p` mp4 (весь файл 218 кадров, без ошибок).

### 2. Цепочка «в стиле продакшена» (OpenCV-декод → zip-трансформация → x264), 3 поколения

Псевдо-монтажная петля: каждый «этап» декодирует предыдущий файл OpenCV,
применяет аффинное масштабирование (zoom 1.3 + смещение) и кодирует обратно.
Референс — lossless PNG после той же первой трансформации.

Метрики по 30 кадрам (генерация 3):

| метрика (планы PSNR в yuv444p) | yuv420p | yuv444p |
|---|---|---|
| PSNR Y | 34.15 | **48.02** |
| PSNR U | 44.93 | **53.72** |
| PSNR V | 49.19 | **53.57** |
| PSNR avg | 38.45 | **50.89** |
| VMAF (mean, 30 кадров) | 92.02 | **93.62** |

Накопление деградации (новая схема): 420-цепочка теряет ~1-2.5 дБ за поколение,
444-цепочка — медленнее (сглаживание меньше); итог на 3-м поколении +12.4 дБ по яркости,
VMAF +1.6 у 444.

### 3. Реальные стадии монтажа (zoom → subtitles → animation)

На реальном исходнике `project_video.MOV` (230 → 218 кадров), static tracking,
timeline zoom:

| стадия | 420p | 444p | комментарий |
|---|---|---|---|
| zoom_out    | 73 495 KB | 93 277 KB | +27% на crf 0 medium |
| subs_out    | 73 702 KB | 105 861 KB | +44% |
| anim_out    | 74 085 KB | 113 665 KB | +54% |

Согласованность геометрии двух режимов: PSNR(420 zoom vs 444 zoom) = 51.2 дБ,
VMAF 99.79 → одна и та же траектория/кадрирование (различия только от кодека).
Соответствие подтверждено тестами `test_zoom_baseline.py` (базовая геометрия без изменений).

Скорость (синтетическая петля, одинаковый контент): 420 ≈ 6.5–7.2 с/ген,
444 ≈ 7.9–8.3 с/ген → кодирование 444 медленнее на ~15–25%.

Память: потребители (OpenCV) читают одинаковые BGR-кадры в обоих режимах —
память не растёт; растёт только размер на диске (см. выше).

## Ограничения / решения

1. На crf 0 preset medium промежуточные 444-файлы заметно тяжелее (+27…54%).
   Если B.1 будет принят и формат включат по умолчанию, стоит отдельно измерить
   промежуточный CRF (например, crf 6–10 для 444) — НЕ сделано в B.1
   (требование п.5: любые изменения CRF/preset — только после измерений и отдельного решения).
2. HDR-исходники: метаданные HDR не копируются в промежуточные файлы — без tonemap
   (явная задача этапа C). BDR-only fallback: при невозможности probe-а цвета
   возвращается пустой список → ffmpeg пишет свои дефолты (нет ложных HDR-меток).
3. Переключение: только env `AUTOMONTAGE_INTERMEDIATE_PIX_FMT` (безопасный режим —
   по умолчанию yuv420p включён). Изменено поведение при недопустимом значении:
   печатается предупреждение, пайплайн использует yuv420p (fail-safe).
4. Ограничение «автозум/траектории/FPS/PTS не меняются» — соблюдено: git diff не
   затрагивает траектории, алгоритмы и тайминги; только параметры кодирования.
