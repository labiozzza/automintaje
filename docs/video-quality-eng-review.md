### 1.3. Технический долг и хрупкость

6. [P1] (confidence: 9/10) Использование `X | None` синтаксиса (Python 3.10+) в `engine.py` при заявленном Python 3.9. Фактически работает (вероятно, благодаря `from __future__ import annotations` или отложенной оценке). Риск: при рефакторинге может сломаться. ### 1.4. Диаграмма выполнения (ASCII)

```
source_video
  → probe (ffprobe) → rotation detection
  → [rotate] ffmpeg libx264 crf0 yuv444p (if 90/270)
  → [mirror] ffmpeg libx264 crf0 yuv444p hflip (if enabled)
  → configs (BigPickle, no encode)
  → [faces] face_tracking.py → apply_face_zoom_v5.py: OpenCV read → transform_frame → ffmpeg libx264 crf0/14 yuv444p
  → [zoom] (combined with faces in current code)
  → [subtitles] apply_auto_subtitles_v2.py: OpenCV read → draw → ffmpeg libx264 crf0/14 yuv444p
  → [animation] apply_timeline_animation.py: OpenCV read → overlay → ffmpeg libx264 crf0 yuv444p
  → [audio_censor] ffmpeg -c:v copy (if enabled)
  → master.mp4 (copy or lossless encode) [NEW in B.2]
  → finalize: ffmpeg libx265 crf14 yuv420p (from master)
  → preview: ffmpeg libx264 crf12 yuv420p (from master)
  → publishers: from master, stream copy if compatible else encode
```

## 4. Performance Review

### 4.1. Время рендера

**Факты:**
- 3 прохода OpenCV→ffmpeg (zoom, subtitles, animation) + 2 финальных (HEVC, H.264) = 5 encode-проходов.
- Каждый проход читает/пишет видео с диска.

**Находки:**
15. [P1] (confidence: 8/10) 5 encode-проходов → время рендера ~5x от одного прохода. Сокращение до 2-3 проходов (мастер + дериваты) даст ~2x ускорение. Рекомендация: Этап B.2.
16. [P2] (confidence: 6/10) yuv444p промежуточные файлы ~1.5x больше yuv420p. Увеличивает I/O. Компенсируется меньшим числом проходов.

### 4.2. Память и диск

17. [P1] (confidence: 8/10) Мастер-файл (Этап B.2) увеличивает пиковое потребление диска. Нужна политика очистки (удалять мастер после создания дериватов, если не diagnostic mode). Рекомендация: реализовать в Этапе B.2.
18. [P2] (confidence: 7/10) Нет мониторинга дискового пространства. Рекомендация: добавить проверку свободного места перед рендером (опционально).

### Отклонённые альтернативы

- **Начать с Этапа C (объединение рендера):** отклонено из-за высокого риска регрессии автозума и сложности тестирования. Потенциальная выгода не перевешивает риск.
- **Full HDR-preserve:** отклонено из-за несовместимости с OpenCV bgr24. Контролируемый SDR-экспорт с документированием.
- **HEVC как мастер-формат по умолчанию:** отклонено до бенчмарка. HEVC медленнее кодируется и может не поддерживаться downstream.
- **Один большой PR:** отклонено. Разбивка на 5 этапов с независимыми коммитами.

## Рекомендуемая архитектура

```
Исходник
  → probe (цвет, FPS, rotation)
  → [rotate] ffmpeg crf0 yuv444p (если 90/270)
  → [mirror] ffmpeg crf0 yuv444p hflip (если включено)
  → configs (BigPickle)
  → [zoom] apply_face_zoom_v5: OpenCV → transform_frame → ffmpeg crf0 yuv444p
  → [subtitles] apply_auto_subtitles_v2: OpenCV → draw → ffmpeg crf0 yuv444p
  → [animation] apply_timeline_animation: OpenCV → overlay → ffmpeg crf0 yuv444p
  → [audio_censor] ffmpeg -c:v copy (если включено)
  → master (copy или lossless, по бенчмарку)
  → finalize: HEVC crf14 yuv420p (из мастера, с цветовыми метаданными)
  → preview: H.264 crf12 yuv420p (из мастера)
  → publishers: из мастера, stream copy если совместимо
```

## Открытые вопросы (блокирующие)

1. **Формат мастера** (D5): требуется бенчмарк в Этапе A. Рекомендация: x264 CRF 0 yuv444p (максимальная совместимость с downstream OpenCV/ffmpeg, без риска несовместимости). FFV1 — только если бенчмарк покажет лучшее качество/скорость.

2. **Instagram FPS** (D7): требуется проверка документации IG Graph API. Рекомендация: оставить 30 fps с документацией, если API не поддерживает другие; убрать принудительный CFR если поддерживает.

## Почему выбранный подход безопаснее альтернатив

1. **Не меняет автозум:** все алгоритмы, настройки, траектории сохраняются. Изменения касаются только кодирования (pix_fmt, CRF, preset, метаданные).
2. **Этапность:** каждый этап — отдельный коммит с откатом. Регрессия локализуется.
3. **Измеримость:** метрики (VMAF/SSIM/PSNR) до/после на каждом этапе.
4. **Обратная совместимость:** API, интерфейс, тесты сохраняются.
5. **Контент-фабрика не затрагивается.**
